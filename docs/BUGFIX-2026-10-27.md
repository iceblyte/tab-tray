## 一、四个上报问题

### BUG-1 点击「添加到分组」无反应

| 项 | 内容 |
|---|---|
| 现象 | 标签头右键有「添加到分组」，点击后什么都不发生 |
| 根因 | 两级原因叠加。① 旧实现把二级菜单注入到菜单项的 DOM 里靠悬停展开，而 Obsidian 的 `.menu` 会裁剪溢出子元素，列表**根本不可见**；② 点击时又因为「已展开」的判断直接 `return`，于是既不显示也不兜底 |
| 修复 | 放弃 DOM 注入。点击后在**下一个宏任务**（`setTimeout 0`）弹出原生二级菜单。延迟是必需的：Obsidian 用 document 级监听关闭菜单，同一次 click 里创建的新菜单会被它立刻关掉 |
| 自验 | 构建产物含 `setTimeout` 分支；菜单项不再有 `is-open` 早退逻辑；`node --check` 通过 |
| 状态 | ✅ 已修复，待人工复验 |

### BUG-2 锁定后标签页没有缩小

| 项 | 内容 |
|---|---|
| 现象 | 固定标签后仍是完整标签，不收缩为图标 |
| 根因 | 旧实现靠「leaf 列表第 N 个 ↔ header 列表第 N 个」配对，这个配对返回了 `null`，于是加类名、隐藏标题、设宽度**全被跳过**。功能看起来是死的，但设置页仍显示可用 |
| 修复 | 改为**从标签头自身**读状态：Obsidian 会给固定标签渲染 `.workspace-tab-header-status-icon.mod-pinned`，直接 `querySelector` 即可。彻底不再依赖 leaf 与 header 的索引关系；popout 窗口按 document 逐个遍历。收缩改用 Obsidian 自己的 `--tab-width / --tab-max-width` 变量，并保留显式宽高兜底 |
| 附带 | 特性探测改为宽松判定（只看实际用到的 `.workspace-tab-header-inner` 与 `-title`）。旧探测要求特定图标元素和 `display: flex`，会误判为不支持并把开关置灰。**已存下的 `compactPinnedRowAvailable: false` 会在下次启动时被重新探测并纠正** |
| 自验 | 构建产物含 `.workspace-tab-header-status-icon.mod-pinned`；新增 5 条配色索引单测（含同名冲突用例） |
| 状态 | ✅ 已修复，待人工复验 |

## 五、第二轮修复（同日，针对人工复验反馈）

### BUG-5 固定后收缩了，但图标不见了

| 项 | 内容 |
|---|---|
| 现象 | 标签收缩成 40px 的方块，里面空白 |
| 根因 | 不是没渲染图标，而是 **Obsidian 主动隐藏了笔记标签的图标**：核心 CSS 有 `.workspace .mod-root .workspace-tab-header[data-type="markdown"] .workspace-tab-header-inner-icon { display: none }`（注释原文 “Hide tab icon if it's a note”）。平时标题占位看不出，收缩后标题被隐藏，就只剩空块 |
| 修复 | 用**同等特异性**的选择器（`.workspace .mod-root .workspace-tab-header.tab-tray-pinned-compact …`）在插件 CSS 里恢复 `display: flex`，并把 `padding-inline-end` 归零让图标居中。只对紧凑标签生效，普通标签仍保持 Obsidian 原样 |
| 附带 | 补上 F4 要求的 tooltip：标题隐藏后把完整文件名写到标签头的 `aria-label`，关闭紧凑模式时还原宿主原值 |
| 自验 | `styles.css` 规则特异性与宿主一致且加载更晚；构建产物含恢复规则 |
| 状态 | ✅ 已修复，待人工复验 |

### BUG-6 只有当前选中的标签右键才有「添加到分组」

| 项 | 内容 |
|---|---|
| 判定 | **Obsidian 限制，不是本项目代码问题**。宿主在 `WorkspaceLeaf.onOpenTabHeaderMenu` 里用 `!this.isVisible() \|\| …` 把 `view.onPaneMenu()` 整段跳过，而 `file-menu` 正是在 `onPaneMenu` 里触发的。后台标签的容器是隐藏的，所以永远收不到事件；连 Obsidian 自己的「重命名 / 删除文件」也只在选中标签上出现 |
| 修复 | 既然拿不到事件，就从**事件本身**拿回菜单：在 `document` 冒泡阶段监听 `contextmenu`，确认 `defaultPrevented`（宿主已处理）且目标是标签头后，调用宿主的 `Menu.forEvent(event)`。它用事件对象做 WeakMap 键，返回的正是宿主刚建好的那个菜单实例；再往里补一项即可。全程不新建菜单、不改选中状态、不注入 DOM |
| 去重 | 选中标签仍会走 `file-menu`，此时菜单里已有同名项，`hasItem()` 直接跳过，不会出现两项 |
| 取文件路径 | 用 `leaf.tabHeaderEl === header` 直接配对，不依赖索引；再 `view instanceof FileView` 取 `file.path`。库外 / 空白标签没有路径，自然不出现 |
| 自验 | 产物含 `Menu.forEvent` 调用与 `defaultPrevented` 守卫；`file-menu` 路径保留作为降级 |
| 状态 | ✅ 已修复，待人工复验 |

### BUG-7 「添加到分组」要悬停展开，而不是点击

| 修复 | 直接 `item.setSubmenu()` 拿到子菜单实例，把分组列表填进去。悬停到右侧展开、带 `›` 箭头、点击外部关闭，全部由宿主处理，和原生菜单完全一致 |

| 细节 | 有子菜单时不再设置前置图标（`folder-plus`），否则会和宿主自动添加的 `›` 箭头并排成两个图标 |
| 自验 | 产物含 `setSubmenu` 调用与 try/catch 降级分支 |
| 状态 | ✅ 已修复，待人工复验 |
