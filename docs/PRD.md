## 1. 产品定位、目标用户与核心痛点

### 1.1 一句话定位（✅）

在 Obsidian 桌面端提供浏览器式的标签「固定 + 分组」收纳体验，并以**「重启后分组绝不丢失」为一等公民质量目标**——这是立项的直接理由（竞品 [Group Tabs](https://github.com/stagars-m/group-tabs) 的 [issue #4](https://github.com/stagars-m/group-tabs/issues/4)：分组跨会话不保存，无人修复）。

### 1.2 目标用户（✅）

1. **重度多标签用户**：并行推进多个主题（研究/写作/项目），标签栏常年 15+ 标签；
2. **被持久化 bug 伤害过的用户**：用过 Group Tabs 等插件、手工搭建的分组结构丢过数据；
3. **从浏览器迁入的用户**：已在 Chrome/Edge/Arc 养成标签分组习惯，期望 Obsidian 有同等能力。

### 1.3 核心痛点（✅）

| # | 痛点 | 现状证据 |
|---|------|----------|
| P1 | 标签栏无结构：几十个标签平铺，无法按主题区分、无法一键收纳 | 用户日常；Reddit 有[公开求帖](https://www.reddit.com/r/ObsidianMD/comments/1pxcm01/any_groupingfolder_plugin_for_the_tabs) |
| P2 | 分组结构是**手工资产**，丢一次重建成本极高，而现有插件的持久化不可靠 | Group Tabs #4（open，无响应） |
| P3 | 固定与分组能力分散在多个互不相干的插件，心智割裂 | 官方插件索引：pin 类 ≥4 个、分组/空间类 ≥3 个，无一覆盖全闭环 |

### 1.4 非目标（✅）

- ❌ 移动端（无桌面式标签栏，无落点）
- ❌ 标签头颜色染色（延后至 v1.1，见 §2.3；且需评估与已有 Color Tab 的差异化）
- ❌ 收费（社区商店生态为免费插件 + 赞助模式）
- ❌ 把多文件合并进一个标签页（那是 Group Tabs 的形态，与本产品「标签仍独立存在」的形态是两种产品）
- ❌ 自由取色器（固定色板足够）

## 2. 核心功能、业务规则与 MVP 范围

### 2.1 v1 功能清单

**F1 分组侧边栏**（✅）
- 位于左侧边栏的视图，ribbon 图标点击打开；
- 分组条目显示：颜色圆点、名称、成员数、**已开计数 n/m**（n = 当前已打开的组员文件数，跨窗格去重）；
- 分组操作：新建、重命名（行内编辑）、改色（固定色板弹层）、删除（**二次确认弹窗**）、拖拽排序；
- 成员操作：悬停 × 移出、拖拽到其他分组、点击成员文件名打开该文件；
- 失效成员显示「丢失」标记（样式区分，不消失）；
- 挂起成员（已钉住）显示 📌 标记（R6），取消固定自动恢复为普通成员。

**F2 展开 / 收起——日常主循环**（✅）
- **展开分组**：把组员文件作为标签打开。默认 = **替换当前窗格**的现有标签（已固定标签一律保留，见 R6）；按住 Ctrl/Cmd = **追加**到现有标签之后（默认替换、修饰键追加，两种都提供）；
- **收起分组**：关闭该组所有已打开成员标签（**跨窗格**）；挂起成员（已钉住，见 R6）**跳过**并提示「N 个成员因已固定未关闭」；
- 成员文件在多个窗格打开时，收起 = 关闭该文件的**所有**标签。

**F3 成员增删入口——共 5 个**（✅）
1. 文件浏览器右键菜单「添加到分组 ▸」（子菜单列分组）；
2. 标签头右键菜单「添加到分组 ▸」；
3. 从文件树把文件**拖入**侧边栏分组；
4. 侧边栏成员条目悬停 × 移出；
5. 侧边栏内拖拽跨组移动。

所有添加入口对**已固定的标签**统一**阻止 + 提示**「该标签已固定，请先取消固定再加入分组」（入口层互斥，Q2 决议 ✅）。

**F4 紧凑固定行——替换模式**（✅ 范围已确认；🔶 实现方式经调研修订）
- 视觉效果：钉住的标签在**所在窗格**标签栏左侧收缩为图标，标题与关闭钮隐藏；
- **实现方式（调研修订）**：不另建独立图标容器，而是对真实 `.workspace-tab-header` **原地重整**——加类名 + 隐藏标题 + CSS 排到左侧。参照 compact-pinned-tabs 的已验证路径：事件驱动（layout-change / pinned-change）而非 MutationObserver、leaf↔header 用 WeakMap 身份映射、防抖同步、**不重写 Obsidian 工作区模型**；
- 图标 = 原生文件类型图标（v1 不做自定义图标——那是 Pinned Tabs Customizer 的领地）；悬停 tooltip 显示完整文件名；
- 左键点击 = 激活该标签；右键 = 原生标签菜单（经官方 `file-menu` 事件挂载，见 §4.3）；中键 = 保持原生行为（关闭并取消固定）；
- 图标过多时自动收缩 / 支持横向滚动；
- Obsidian 原生 pin 状态即唯一事实源（✅ 已验证：pin 随 workspace.json 持久化、重启自动恢复），插件不另存钉住状态。

**F5 持久化引擎——产品存在的理由**（✅）
- 存储：`.obsidian/plugins/tab-tray/data.json`（用户选定，接受跨设备漫游依赖同步方式的后果）；
- **每次成员/分组变更立即防抖写盘（≤500ms），绝不依赖退出时机**；
- 原子写（临时文件+替换；若 DataAdapter 不支持原子 rename，则采用「先写副本再替换主文件」的等效策略，机制在开发期验证 ❓）；
- 始终保留上一份完好副本 `.bak`；
- 加载时主文件解析失败 → 自动回退 `.bak` 并向用户弹提示；
- 数据含 `schemaVersion` 字段，预留迁移路径。

**F6 命令面板**（✅）
- 每个分组动态注册：「打开分组：<名>」「收起分组：<名>」（用户可自绑快捷键）；
- 全局命令：「新建分组」「收起当前分组的标签」「打开分组侧边栏」；
- 命令不依赖侧边栏视图处于打开状态。

**F7 重命名自动跟随**（✅，对第一轮「失效标记」决策的精化）
- 插件运行期间，通过 vault `rename` 事件自动更新组内路径；
- 「失效标记」保留为兜底：仅覆盖 Obsidian 关闭期间外部发生的移动/重命名。

**F8 双语**（✅）：zh-CN + en 文案表自第一天建立；社区商店页用英文。

### 2.2 业务规则

| # | 规则 | 状态 |
|---|------|------|
| R1 | 分组成员绑定**文件路径**（重启后标签实例全部重建，无跨会话身份；路径是唯一可持久绑定物） | ✅ |
| R2 | 一个文件**同一时刻只属于一个分组** | ✅ |
| R3 | 分组定义在 **vault 级共享**（同 vault 所有窗口、所有 workspace 同一套），数据文件天然按 vault 隔离 | ✅ |
| R4 | 文件失效（删除/移动且无事件跟随）→ 组内标记「丢失」，**绝不静默删除** | ✅ |
| R5 | **钉住与分组入口互斥**：本插件所有添加入口拒绝已固定标签（阻止+提示）；但 Obsidian 原生钉住无法拦截（无官方手段移除原生菜单项），成员被原生钉住时进入**挂起**状态（R6）而非移出分组 | ✅ |
| R6 | **挂起-回归**：挂起成员在侧边栏显示 📌、收起/展开替换均跳过、取消固定后自动恢复为普通成员；钉住状态运行时从原生 leaf 状态派生，data.json **零新增字段** | ✅（Chrome 心智模型，第四轮 Q1 决议） |
| R7 | 任何可打开的文件类型可入组（md / canvas / pdf / 图片等）；无路径的未保存新标签不可入组（尝试时提示） | ✅ |
| R8 | 固定色板约 10 色，适配明暗主题；不做自由取色 | ✅ |
| R9 | 允许空分组；分组数/成员数不设硬上限（超软阈值提示） | ✅ |
| R10 | 卸载/禁用插件**不清理** data.json（数据是用户资产） | ✅ |

### 2.3 明确排除在 v1 之外（暂定路线图）

| 功能 | 去向 | 理由 |
|------|------|------|
| **按分组染色**（组色环绕成员标签头，Chrome 胶囊式；**单文件不染色**） | v1.1 已确认方向 | ✅ 用户确认。与 Color Tab / Tab Tint（按单文件）形成正面差异化；执行时仍是无官方 API 的灰色地带，需特性检测+静默降级 |
| 固定行图标显示所属分组颜色角标 | v1.1 候选 | 依赖 v1 先站稳挂起-回归模型 |
| 「钉住整组」 | v1.1+ 候选 | 与入口互斥模型有张力，需单独设计 |
| 自由取色器、移动端、单标签合并形态 | 不做 | 见 §1.4 |

## 3. 竞争差异化与用户留存逻辑

### 3.1 已验证的竞争格局（来源：官方社区插件索引逐条描述 + 官方 changelog）

**平台事实**：截至 2026-10（Desktop 1.13.x），Obsidian 原生**没有**命名/彩色标签分组、没有标签颜色、未改动固定标签；changelog 中 "tab group" 一词均指原生「窗格 = 一组标签」的内部概念。产品立足点成立。

**竞品地图**（✅ 均经深查：官方描述 + 仓库/源码 + obsidianstats 数据）：

| 插件 | 做什么 | 体量 | 与本产品的重叠 |
|------|--------|------|----------------|
| [Group Tabs](https://github.com/stagars-m/group-tabs) | 多文件合并进一个原生标签 | 972 下载，12 commits，1 star | 形态不同；其 issue #4（组跨会话丢失，open 无响应）是本产品立项契机与反面教材 |
| **Pinned Tabs**（compact-pinned-tabs） | Chrome 式紧凑固定行：对真实标签头**原地重整**、自定义图标、防误关、重启后图标修复 | ~1k 下载，审查标记 Excellent + Caution | **重叠 F4**；无分组能力。实现参照价值最高 |
| **Working tabs** | **pane 即空间**：自动成组、侧栏切换、Hide=后台驻留、Complete=关闭、自动配色、按路径 reconcile、批量写盘 | 980 下载，0 issue | **概念最直接的竞品（F2）**，但活在 pane 维度：无紧凑固定行、不在原生标签栏内做分组 |
| [Color Tab](https://community.obsidian.md/plugins/color-tab) | 右键给标签上色（5 色槽，**按单文件**） | ~1k 下载 | 本产品 v1.1 染色已确认为**按分组**（Chrome 式）——正面差异化成立；其源码证明 tab 右键菜单走官方事件可行 |
| [Vertical Tabs (oxdc)](https://vertical-tabs-docs.oxdc.dev/User-Guide/feature-tour) | 垂直标签视图：组=原生 split、重命名/折叠/Zen/聚焦、Mission Control(beta 配色)、临时标签、导航策略 | **87,387 下载**，625 stars，11 天前仍发版 | **最强威胁**。MIT 免费（仅 beta 收 $2.99/月）；但不做紧凑固定行、不把分组画进原生标签栏；历史上也踩过工作区恢复 bug（#136） |
| 固定类周边：Pinned Tab Utils / Pinned Tabs Row / Shrink pinned tabs / Pinned Tabs Customizer | 固定标签的左移 / 独立行（纯 CSS grid）/ 收缩 / 图标定制 | 104~509 下载 | 局部重叠 F4；Pinned Tabs Row 证明纯 CSS 排布可行（需 Obsidian 1.13+） |
| Contexts 类（Contexts / Context Workspaces 等） | 保存当前标签集为命名 context，**切换=替换式**，只存相对路径 | 体量很小 | 与「展开分组」语义同源；其 sync-safe 路径策略与本产品 R1 一致 |
| Tab Group Arrangement | 只做已拆分窗格的布局排列 | 1-2 年未更新 | 无实质重叠（其 "group" 指原生窗格） |

**格局结论**（✅）：赛道**人多但都很小**——除 Vertical Tabs（87k）外，所有相关插件 <1.1k 下载，多为 0.1.x 或停更状态；且**人人都摔过同样的坑**：Group Tabs #4 组消失、Vertical Tabs #136 工作区状态不恢复、固定/染色类全员依赖内部 DOM 或未公开属性。**没有任何插件同时覆盖「原生标签栏内的命名分组收展 + 紧凑固定行 + 以持久化为第一质量目标」**——这是 Tab Tray 的立足点。「原生标签栏内」这个限定词必须守住：跟 Vertical Tabs 比视图形态、跟 Working tabs 比 pane 空间，都是以小博大。

### 3.2 差异化主张

- **D1 原生标签栏内的唯一闭环**：分组（建/收/展/排序/配色）+ 固定（紧凑行）在一个数据模型内协同，正交而不冲突。与最近竞品的语义分野：Vertical Tabs 的分组活在独立垂直视图里；Working tabs 的空间活在 pane 维度且 Hide=后台驻留（标签不真关、内存持续占用）——Tab Tray 的收起是**真关闭、按路径重开**，内存与心智都更轻；
- **D2 持久化即产品**：写盘策略是结构性防御而非「测过没复现」，且验收矩阵公开（§6）——直接对 issue #4 类创伤用户喊话；
- **D3 与原生生态共生**：复用原生 pin 与原生菜单，不劫持、不另立事实源，Obsidian 升级时的破坏面最小。

### 3.3 用户留存逻辑

1. 分组结构是**手工积累的资产**，用得越久迁移成本越高（R10 保证卸载也不丢）；
2. 展开/收起 + 命令快捷键构成高频日常循环，功能黏性来自使用频次而非功能数量；
3. 已开计数、丢失标记让用户随时信任「数据都在」——信任即留存。

## 4. 商业模式、成本假设与技术约束

### 4.1 商业模式（✅）

- MIT 开源、免费，提交 Obsidian 社区插件市场；
- 赞助链接：**https://afdian.com/a/iceblyte**，放置于 README 与设置页「关于」区。

### 4.2 成本假设（✅ 基线 / 🔶 推导值）

- solo 开发、AI 辅助、每周数小时（✅ 用户确认的投入画像）；
- 发布后至少维护 6 个月（✅）；
- 🔶 由上推导：v1 目标 4~6 周出可自用版本，再 2 周 dogfood 后提交市场——此排期是假设而非承诺。

### 4.3 技术约束

| 约束 | 影响 | 状态 |
|------|------|------|
| 侧边栏视图、命令、file-menu 走官方 API | 稳定面 | ✅ 官方能力 |
| 紧凑固定行对标签头做原地重整（类名 + CSS） | Obsidian 升级可能破坏 → 特性检测 + 静默降级（失效则不生效并提示，分组功能不受影响，Tab Tint 模式：失效不崩溃） | ✅ 已确认接受 |
| 标签右键菜单（F3-2） | 走官方 `file-menu` 事件（`source: "tab-header"`，Color Tab / Tab Tint 源码实锤）；该 source 串是事实标准而非文档明列 → 保留 DOM contextmenu 兜底 | ✅ 已验证（附兜底） |
| 原生 pin 随 workspace.json 持久化、重启自动恢复 | 固定行重启后从恢复的 pin 零成本重建；插件不存 pin、不重复造事实源 | ✅ 已验证（多源交叉） |
| data.json 跨设备漫游 | 官方 Obsidian Sync 开启配置同步时同步插件 data.json；Syncthing 类取决于用户是否同步 `.obsidian` | ✅ 已验证（写入用户文档） |
| DataAdapter 提供 `rename` 与原子 `process` | F5 崩溃安全写有官方支撑：临时文件 + rename，或小文件直接 `process` | ✅ 官方 API |
| TypeScript + esbuild 标准插件工具链 | — | ✅ |

| R7 | Vertical Tabs（87k 下载、活跃发版）未来把紧凑固定行或标签栏内分组补进版图 | 中 | 快发布抢位；守住「原生标签栏内」细分；与垂直视图形态正交，二者可并存 |

## 8. 独立审查记录

成稿后对本 PRD 做了一轮独立审查，发现并处置如下：

1. **发现设计空洞（已补 R6，🔶 待用户确认）**：「展开=替换当前窗格」与「钉住正交」在质询中未被同时推演——替换若不跳过钉住标签，会关掉用户明确要求保留的东西。补规则 R6：展开替换时跳过已固定标签（与收起对称），替换后窗格 = 钉住标签 + 组员标签。**此条是审查新增，基线确认时请单独过目。**
2. **措辞矛盾修正**：原「分组全局共享」易误读为跨 vault——已统一表述为「vault 级共享」（R3），与 data.json 存储位置一致。
3. **遗漏补齐**：命令不依赖侧边栏打开（F6）；卸载不清理数据（R10）；侧边栏丢失标记样式（F1）；schemaVersion 迁移预留（F5）；视图未开时计数仍需更新（T2 依赖 T1 的事件机制）。
4. **过度设计检查**：五入口共享一个变更 API（砍任一入口不省实质工作量）；动态命令、删除确认、软提示均有质询确认依据——无过度设计项。
5. **不可验证描述清理**：「分组不能消失」已全部转译为 §6.2 矩阵的可测条目；「持久化可靠」不作为验收句出现；所有未证实平台事实（H1–H8）以 ❓ 标注，无一处当作事实使用。
6. **遗留开放项**：H1/H2（竞品深查）与 H8（需求信号）等待后台调研报告回收后更新 §3/§5；若报告推翻「赛道碎片化」结论，将回到基线确认前修订。

**v1.1 增补（调研报告回收后的第二轮审查）**：

7. **实质修订两处**：F4 实现方式从「独立图标行容器」改为「对真实标签头原地重整」——前者缺少先例，后者有 compact-pinned-tabs 的已验证路径（事件驱动、WeakMap 映射、不重写工作区模型），视觉效果不变；D1 的「唯一闭环」收窄为「**原生标签栏内**的唯一闭环」——Vertical Tabs 与 Working tabs 各自覆盖了相邻形态，笼统的「唯一」守不住。
8. **四个平台假设全部落定为好消息**（H3 右键菜单官方事件 / H4 pin 持久化 / H5 Sync 同步 data.json / H6 原子写 API），V0 spike 从三项验证缩为两项快速确认；R4（Sync 漫游落空）降级为低。
9. **新增 R7**：87k 下载的活跃巨头（Vertical Tabs）未来进场挤压，缓解 = 快发布 + 守「原生标签栏内」细分。
10. **修订不推翻基线**：数据模型、v1 范围、交互语义、存储决策均未被调研动摇；Working tabs 的 Hide（后台驻留）与本产品收起（真关闭）的语义差异已写入 D1 作为卖点。**基线确认仍待用户，R6（展开替换跳过钉住标签）仍为待确认新增条款。**

**v1.2 增补（Chrome 心智模型对齐，第四轮质询）**：

11. **R5/R6 重写**：用户以 Chrome 为基准校准——固定与分组入口互斥、染色只作用于分组。原「正交 + 静默跳过」升级为「**入口互斥 + 挂起-回归**」：Obsidian 原生钉住无法从菜单层拦截（与 Chrome 的关键环境差异），故成员被原生钉住时挂起而非逐出——📌 可见标记、收起/替换跳过、unpin 自动回归，钉住状态运行时从 leaf 派生、data.json 零新增字段。R6 的 🔶 待确认状态解除（Q1/Q2 决议）。
12. **按分组染色升级为已确认方向**（v1.1）：单文件不染色，与 Color Tab / Tab Tint 形成正面差异化；H7 从 ❓ 降格为 🔶（仅剩执行时机与维护成本未知）；Color Tab 对照已更新至 §3.1；验收新增 A9（挂起-回归闭环）。
